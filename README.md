# ScribeDesk 同义纠错检索组件

TypeScript 实现的只读检索组件：编辑距离纠错 + 多跳同义词扩展 + 字段加权评分。
输入假定已完成 Markdown 解析、分词、NFC 归一化与小写化；构建后数据只读。

## 使用

```ts
import { build } from "./src/index.js";

const retriever = build(pages, synonyms); // pages/synonyms 均为迭代器，只消费一次
const hits = retriever.search(["fuzzy", "rare"], 20); // -> [{ id, score }, ...]
```

- `pages`：每页含唯一整数 `id` 与 `title` / `tags` / `author` / `body` 四组词元。
- `synonyms`：有向边 `{ from, to, w }`，`w` 为 0–1000 整数。
- `query`：1–4 个词元（重复自动去重）；`k`：1–20。
- 返回按分数降序、id 升序的精确前 k 名。

## 语义

- 每个查询词元以置信度 1000 起步；词表中与其编辑距离恰为 1（Unicode 码点，
  仅插入/删除/替换）的词以 600 引入，纠错只发生在起点。
- 同义边可多跳、可有环；过边后置信度为 `floor(conf * w / 1000)`，取所有路径最大值，
  零置信度不算命中。
- 字段权重 title=8、tags=4、author=2、body=1；某查询词元对页面的贡献为所有命中
  （扩展词 × 字段）上 `置信度 × 字段权重` 的最大值；页面须命中每个查询词元，总分为各项之和。

## 实现要点

- **纠错索引**（`src/correction.ts`）：对称删除索引。为词表每个词建立
  `{词本身} ∪ {全部单字符删除}` 的键，查询时用同样的键集合命中候选，再做一次精确
  距离 1 验证（共享删除键是必要非充分条件，如 `ab`/`ba`）。无需遍历全词表。
- **同义扩展**（`src/index.ts` 内 `expand`）：边权 ≤ 1000 保证置信度沿路径不增，
  用最大堆做 best-first 松弛，词出堆即定置信度；环自然收敛。基于 wordId 的 CSR
  邻接结构，无字符串开销。
- **倒排索引**：构建时把 `(词, 页, 字段)` 三元组写入动态增长的原型数组，
  计数排序压缩为 CSR（`postingStart/postingPage/postingMask`），同页多字段合并为
  位掩码；页 id 映射为稠密下标，评分用戳记数组复用，避免每查询分配。
- **评分与求交**：每个查询词元独立评分到稠密数组，从最小候选集出发求交，
  用容量为 k 的最小堆取精确前 k（不截断扩展词与候选页，不全排序）。
- 无查询结果缓存；跨查询仅复用定长暂存缓冲。

## 构建与测试

干净机器（仅 Node.js）上：

```sh
npm install
npm test        # tsc 编译 + node:test 单元/对照测试
npm run bench   # 规模基准：10 万页 / 800 万词元 / 3 万词 / 10 万边
```

测试（`test/`）含独立全量参考实现（`test/reference.ts`，暴力 DP 编辑距离 +
不动点松弛 + 全量排序），覆盖：低权重直达边不敌多跳、权重 1000 的环、多纠错起点
汇合取最大值、非 BMP 字符的插入/替换、字段权重与 max-not-sum、高频词+稀有词联合
查询（最终命中页在各单项排名 20 名之外）、零置信度边不命中，以及 30 组随机语料
与参考实现的全量对照。

基准（`bench/`）：`bench/generator.ts` 为确定性（ seeded ）生成器，产出 10 万页、
去重后 800 万词元、3 万词词表、10 万条同义边，60% 页面共享高频词；50 个互不相同
的查询各含高频词的一个编辑距离 1 近邻与一个稀有词。`bench/bench.ts` 报告 p50/p95/max
延迟与峰值 RSS（分阶段采样），p95 > 200ms 或峰值 RSS > 512MiB 时以非零码退出。
计时样本为 50 个不同查询，无结果缓存。

本机参考结果（seed=42）：构建约 1.5s（不计入查询指标），查询 p95 ≈ 78ms，
峰值 RSS ≈ 380MiB。
