# ScribeDesk 同义纠错检索组件

TypeScript 实现的只读全文检索组件：编辑距离纠错 + 有向加权同义词多跳扩展 + 字段加权评分。

## 使用

```ts
import { build } from './src/index.js';

const searcher = build(pages, synonyms);   // pages/synonyms 为可迭代对象，构建后数据只读
const hits = searcher.search(['quer', '词元'], 20); // => [{ id, score }, ...] 分数降序、id 升序
```

- 输入词元需已完成 Markdown 解析、分词、NFC 归一化与小写化（不在本组件内）。
- 查询词元 1..4 个（自动去重），k 1..20。
- 页面必须命中每个查询词元；总分为各词元贡献之和。
- 词元贡献 = 所有命中扩展词与字段中 `置信度 × 字段权重` 的最大值（title 8 / tags 4 / author 2 / body 1），不按出现次数或路径数量累加。

## 评分规则

- 查询词元本身以置信度 1000 作为起点；词表中与其编辑距离恰为 1（码点级插入/删除/替换）的词以置信度 600 作为起点，纠错只发生在起点。
- 沿有向同义边多跳扩展：经过边后置信度为 `floor(置信度 × w / 1000)`，同一扩展词取所有起点与路径中的最大值，零置信度不算命中。

## 设计要点

- **纠错**：删除邻域索引（词本身 + 删除一个码点的所有变体排序后做 CSR，查询时二分 + 精确验证），不遍历全词表。
- **同义扩展**：边权 ≤1000 即乘子 ≤1，用最大堆做 Dijkstra 式传播，得到每个词元的最大置信度，天然支持多跳与环。
- **倒排**：每字段一份 termId → pageIdx 的 CSR 倒排；构建期用分块 `Uint32Array` 收集，控制峰值内存。
- **Top-k**：以命中页面数最少的查询词元驱动交集，用容量 k 的有界堆流式取前 k 名，不做全量排序、不截断扩展词与候选页。

## 构建与测试

```sh
npm install
npm test        # 编译 + 单元/回归/中规模参考核对测试
npm run bench   # 全规模基准：100k 页 / 8M 词元 / 30k 词 / 100k 边
```

基准生成器位于 `bench/generator.ts`，固定种子（默认 20261006，可用 `npm run bench -- <seed>` 覆盖），
可重复生成相同数据；60% 页面共享高频词，50 个查询各含该高频词的一个模糊近邻与一个稀有词。
组件不做查询结果缓存，每个计时样本都是完整独立计算。

本机最近一次基准结果（Apple Silicon，Node 24）：

```
pages=100000 tokens=8000000 edges=100000 pagesWithCommonWord=60000 (60%)
latency ms: mean=49.7 p50=51.1 p95=53.8 max=57.7
peakRSS=410 MiB (上限 512 MiB)
```
