# dialogue-answer-matcher

对话练习的可接受回答匹配库（TypeScript）。装入一组回答模板后，对学习者提交的一句回答做整句相似度判定；模板与判定数据只存内存，不处理会话推进。

## 使用

```ts
import { AnswerMatcher } from "dialogue-answer-matcher";

const matcher = new AnswerMatcher([
  { segments: [["早", "早上"], ["好", ""], ["呀", ""]] },
]);

matcher.judge("早上好呀");
// { score: 1, passed: true, answer: "早上好呀" }
```

- 每个模板由有序片段组成，每段 1–3 个可选字符串（可为空串）；从每段恰选一个按序拼接（不自动加空格）即得一条合法回答，整组模板表达的全部回答都参与判定。
- `judge(submission)` 返回 `{ score, passed, answer }`：全体合法回答中的最高相似度、是否达到 80%（恰好 80% 算达标，按未四舍五入的整数比例判断）、一条取得该分数的合法回答；未达标时也返回全局最高分与对应回答。
- 比较以 Unicode 码点为单位；大小写、空格、标点均参与比较，不做任何自动转换。
- 相似度 = 1 − d / max(两句码点长度)，d 为码点级编辑距离；两句均空为 1，仅一句为空为 0。
- 约束：≤4 个模板、每模板 ≤48 片段、每段 ≤3 个选项、每选项 ≤4 码点、提交 ≤128 码点；越界抛 `RangeError`。

## 算法

合法回答数量可达 3^48 量级，无法枚举。库把每个模板编译为链式自动机（空选项为 ε 边），在（自动机状态 × 候选长度 × 提交前缀）上做编辑距离动态规划，接受态处按 (长度, 距离) 取整数值最优相似度（整数交叉相乘比较，避免浮点误差），再从 DP 表回溯出一条最优合法回答。装入后无状态，可反复判定。

## 构建与测试

```sh
npm install
npm test        # 构建 + node:test 正确性测试 + 上限规模性能实测
```

只依赖 `typescript` 与 `@types/node`（devDependencies），测试使用 Node 内置 `node:test`，无需其他服务。

## 实测资源（上限规模：4 模板 × 48 片段 × 3 选项 × ≤4 码点，提交 128 码点）

本机（Node.js 24）实测，由 `npm test` 中的 `test/perf.mjs` 输出：

- 装入耗时：约 8 ms（上限 5000 ms）
- 单次判定：约 45–64 ms（上限 5000 ms）
- 进程峰值内存：约 134 MiB（含 Node 基线约 44 MiB，上限 256 MiB）
