# 对话练习可接受回答匹配库

TypeScript 实现的单轮文本判定库：为同一道对话题登记多种正确表达（模板组合），
对学习者的单句回答按整句相似度判定是否达到 80% 标准。模板与判定数据只存内存，
不涉及会话推进。

## 使用

```ts
import { AnswerMatcher } from "dialogue-answer-matcher";

// 每个模板 = 有序片段数组；每段恰选一个选项，按原顺序直接拼接（不加空格）。
const matcher = new AnswerMatcher([
  [["你好", "您好"], ["，", ""], ["老师", "李老师"], ["好", "。"]],
]);

const result = matcher.judge("您好，李老师好");
// { similarity: 1, passed: true, answer: "您好，李老师好" }
```

- `similarity`：全体合法回答中的最高相似度（未四舍五入）。
- `passed`：最高相似度是否 ≥ 80%（恰好 80% 也算达标，按有理数精确判定）。
- `answer`：一条取得最高分的合法回答；未达标时也返回全局最优句。

## 判定规则

- 比较以 Unicode 码点为单位；大小写、空格、标点均参与比较，不做归一化。
- 编辑距离 = 插入/删除/替换单个码点的最小操作数（各代价 1），可跨片段边界。
- 相似度 = 1 − d / 两句码点长度的较大值；两句均空为 1，仅一句为空为 0。
- 得分是所有合法回答中的最高相似度（不是编辑距离最小者的相似度）。

## 算法

合法回答数量可达 3^192 量级，无法枚举。每个模板展开为无环字符自动机（DAG），
在 (自动机状态, 已匹配目标前缀, 已生成长度) 上做动态规划，精确求出每个可能
长度的合法回答与学习者回答的最小编辑距离，再按长度折算相似度取最大值；
最后从接受状态反向回溯出一条最优句。判定不保存任何跨调用的状态。

规模上限：4 模板 × 48 片段 × 3 选项 × 4 码点；学习者回答 ≤ 128 码点。

## 构建与测试

```sh
npm install
npm test
```

只依赖 Node.js 与 devDependencies 中的 `typescript`、`@types/node`，
不需要数据库、缓存、消息队列或任何监听端口的服务。

## 实测资源（上限规模：4×48×3×4，回答 128 码点）

本机（macOS, Node v24）实测，限值均为 5 秒 / 256 MiB：

| 指标 | 实测 | 限值 |
| --- | --- | --- |
| 装入 4 个上限模板 | ≈ 2 ms | < 5 s |
| 单次判定（128 码点回答） | ≈ 65–87 ms | < 5 s |
| 进程峰值 RSS | ≈ 121 MiB | < 256 MiB |

测试覆盖：空选项与空句约定、跨片段编辑、补充平面字符（码点而非 UTF-16 单元）、
“编辑更少但相似度更低”的候选取舍、恰好 80% 与略低于 80%、300 组随机小模板
与暴力枚举完全一致、上限规模精确匹配与连续判定独立性、超限输入拒绝。
