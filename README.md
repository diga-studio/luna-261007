# VaultMint 分币估值账本

单资产代币的估值账本（TypeScript 实现，仅内存态）。发行量 `N` 固定，估值 `V`
以整数美分记账（`bigint`，可超过 `Number.MAX_SAFE_INTEGER`）。每位持有人的
分配金额由**当前估值与当前持仓**完全决定，与转账路径、加入顺序无关。

## 分配规则

设持有人 `i` 持币 `q_i`，则：

- 基础金额 `base_i = floor(V * q_i / N)`，余数 `r_i = (V * q_i) mod N`；
- 令 `K = V - Σ base_i`，恰好余数最大的 `K` 位持有人各多得 1 分；
- 余数相同按持有人 ID 的 ASCII 字典序优先；只有正余额持有人参与排名。

全程使用整数（`bigint`）运算：不做单枚价格舍入，不用浮点决定金额、余数或排名。

## 设计：为什么转账不需要全量重算

关键观察：余数总和恒等于 `N * K`（因为 `Σ V*q_i = V*N = N*Σbase_i + Σr_i`）。
一次转账只改变两个账户的持币量，每个余数的变化量都小于 `N`，因此
**`K` 每次转账最多变化 1**。于是：

- 每个账户缓存 `base` 与 `remainder`，转账时增量维护 `K`（`O(1)` 次 bigint 运算）；
- 排名结构是一棵**带子树大小的随机 treap**，键为 `(remainder, id)`，
  排序为余数降序、ID 升序——与奖金规则的字典序完全一致；
- 持有人是否获得 +1 分 ⇔ 其键的排名 `rank ≤ K`，由 treap 的
  order-statistics 查询在期望 `O(log H)` 内回答；
- 转账只需对最多两个账户做删除/重新插入（余数变化）并增量更新 `K`；
  清仓账户从 map 与 treap 中**物理删除**，不为离场账户保留任何记录。

金额不在转账时写回任何账户：`quote` 时按 `base + (rank ≤ K ? 1 : 0)` 现算，
因此未参与交易者的金额变化（`K` 或排名边界移动所致）自然被反映，
无需触碰他们的记录。

## 复杂度

设 `H` 为当前正余额持有人数：

| 操作 | 时间 | 说明 |
| --- | --- | --- |
| `create` | `O(H log H)` | 逐账户插入 treap（允许全量处理） |
| `transfer` | 期望 `O(log H)` | 至多 2 次删除 + 2 次插入 + `O(1)` 增量维护 |
| `reappraise` | `O(H log H)` | 全量重算余数并重建 treap（允许全量处理） |
| `quote` | 期望 `O(log H)` | 一次排名查询 + `O(1)` bigint 运算 |

空间 `O(H)`：每个正余额持有人一个 map 条目 + 一个 treap 节点；
不为每枚代币建记录，不预存答案，不保留离场账户。

## 不变式

任意操作完成后（实现与测试均逐步核验）：

- `Σ q_i = N`（转账只搬运、reappraise 不动持仓）；
- `Σ amount_i = Σ base_i + K = V`（`K` 的定义即保证）。

## 运行

```sh
npm install   # 仅需 typescript（devDependency）
npm test      # 编译并运行全部测试
```

## 测试覆盖（`test/ledger.test.ts`）

- **规格固定用例**：`N=100, V=4`，A/B/C/D 各持 10/20/30/40。A→C 转 10 枚后，
  未参与交易的 D 从 2 分变为 1 分；反向转回后全部金额恢复。
- **随机对照测试**：与独立的全量重算参考模型逐步比对——大量相同余数
  （高度重复的持币量）、清仓退出与重新加入、超过 `Number.MAX_SAFE_INTEGER`
  的估值与重估；每次操作后逐账户核验金额并核验 `Σq=N`、`Σamount=V`。
- **规模测试**：10 万持有人、2 万次转账 + 6 万次穿插查询（含新增与离场账户、
  穿插重估），记录并打印各阶段耗时；周期性及最终全量核验守恒与逐账户金额。
