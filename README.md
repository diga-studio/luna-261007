# clinic-slot-allocator

门诊连续号源分配库（纯 TypeScript，进程内运行，无接口层）。针对「只检查预约开始时刻」
导致的错误推荐问题，本库按**每一分钟**精确判断容量，找出能够完整容纳本次诊疗
（15 / 30 / 60 分钟）的最早时段，并在预约与取消后即时反映剩余号源。

## 环境要求

- Node.js >= 22.6（利用原生 TypeScript 类型擦除直接运行 `.ts`，无需编译步骤）
- `npm install` 仅安装 `typescript`（用于 `npm run build` 类型检查）

## 使用

```ts
import { SlotAllocator } from "./src/index.ts";

const alloc = new SlotAllocator();

// 每位医生设置一次不可变开放日历；区段互不重叠，容量 1..8，[start, end) 含头不含尾
alloc.setCalendar("doc-1", [
  { start: 0, end: 480, capacity: 2 },
  { start: 480, end: 720, capacity: 1 },
]);

// 最早可预约时段查询（不占用号源）；返回开始分钟或 null
const t = alloc.findEarliest("doc-1", 0, 720, 30);

// 指定时段占用：全程每分钟都有剩余容量才成功，否则不留任何占用
const id = alloc.book("doc-1", 100, 30); // 成功返回唯一 id，失败返回 null

// 按 id 取消；重复取消是 no-op（返回 false），不会重复释放容量
alloc.cancel(id);
```

时间统一为 Unix 纪元以来的整数分钟，区间含开始、不含结束，不涉及本地时区。
预约开始时间可以是任意整数分钟，不要求按时长对齐；允许跨越首尾相接的日历
区段，但不能跨越未开放的空档。

## 实现说明

- 每位医生独立维护一份「剩余容量区间」序列，按块（block）组织，每块约 512 个
  区间；块内记录 `min/max` 剩余容量与「连续可约分钟数」的前缀/后缀/最大值聚合。
- 查询：按块扫描，整块全可约/全不可约时 O(1) 跳过，只在答案所在块内下钻到区间
  级别，复杂度 O(块数 + 块大小)，与预约密度无关。
- 占用/取消：定位到涉及块，就地拆分区间并 ±1，随后重算块聚合；块过大时二分。
- 占用前先整段校验 `rangeMin >= 1`，失败时不产生任何修改；取消按预约 id 精确
  释放原区间，重复取消直接忽略。

## 脚本

- `npm test`：单元测试（容量 >1、部分重叠、端点相接、跨容量边界、跨空档等）
  + 随机交错操作与独立逐分钟参考实现的完整对拍（含取消全部预约后恢复初始结果
  的校验）。
- `npm run stress`：规模压力测试（100 医生 / 2000 日历区段 / 20 万有效预约 /
  20 年跨度，5 万查询与 1 万占用/取消交错）。单独报告初始化耗时，操作耗时要求
  < 15 s、峰值 RSS < 384 MiB，并对抽样查询做独立核验（时段确实可用且无更早答案）。
- `npm run build`：`tsc` 全量类型检查（不产出文件，库以 TS 源码形式被直接引用）。
