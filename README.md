# retention-allocator

AIA 进度付款申请（G702/G703）扣留款整批分摊库。由上层财务程序调用，
批次输入与计算结果只保存在进程内，无任何外部依赖与持久化。

## 规则

- 扣留比例固定 10%；首期期初累计扣留款为 0；不涉及扣留款释放。
- 每项每期累计扣留款只能取精确 10% 金额向下或向上取整到分的结果；
  精确金额已是整数分时保持该值。
- 同一期各分项累计扣留款之和 = 该期项目累计金额合计的 10% 四舍五入到分
  （恰好半分时向上进一分）。
- 每个分项的累计扣留款随期次不减少；本期新增 = 本期累计 − 上期累计。
- 在满足以上规则的完整方案中，取所有分项、所有期次偏差总和最小者
  （偏差以十分之一分计：|累计扣留×10 − 累计金额|）。
  并列时按期次从早到晚、同期按输入分项顺序，在第一处不同位置取数值较小者。

## 用法

```ts
import { allocateRetention } from "retention-allocator";

const result = allocateRetention({
  amounts: [
    [4, 4], // 分项 A 各期累计已完工程与在场材料合计（整数分）
    [2, 9], // 分项 B
  ],
});
// result.cumulative[i][t]：分项 i 第 t 期累计扣留款（分）
// result.current[i][t]：分项 i 第 t 期本期新增扣留款（分）
```

输入 `amounts[item][period]` 为整数分，每个分项的累计金额必须随期次不减少，
否则抛出异常。输出仅保留在返回对象中，调用方自行决定后续处理。

## 实现

整批核算建模为时间轴上的区间覆盖最小费用流（`src/retention.ts` +
`src/minCostFlow.ts`）：每个分项在 floor(金额/10) 相等的连续期段内，
扣留款的“进位”构成后缀区间；各期列和约束化为节点供需；
费用用 BigInt 叠加“偏差增量 × 2^M + 字典序权重”，一次求解同时保证
全局偏差最小与规定的并列次序。

## 构建与测试

只装 Node.js 的干净机器上：

```sh
npm install
npm test
```

测试覆盖：两个规格用例（整批最优 17 个十分之一分偏差、单期并列次序与
可重复性）、半分进位、精确 10% 保持、输入校验，以及 300 组随机小批量
与暴力枚举的全局最优性/并列次序对拍。
