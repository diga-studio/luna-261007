# succession-planner

无状态的继任覆盖规划库。多个关键岗位争用同一批员工时，给出一份跨就绪时点
一致的候选预留方案（岗位 ↔ 员工配对），而非逐岗位推荐名单。

## 使用

```ts
import { planSuccession } from "succession-planner";

const plan = planSuccession({
  positions,   // 岗位及其技能要求 (required 1-5, weight 1-100)
  employees,   // 员工技能画像 (actual 0-5, 缺失按 0)
  candidates,  // 每个岗位的候选人名单 (readiness 0/1/2)
});
// plan.reservations: 预留配对; plan.c0/c1/c2/maxGap/totalGap: 五项指标
```

构建与测试：`npm install && npm test`（仅需 Node.js）。

## 最优性

`planSuccession` 返回全局精确最优解，按字典序依次优化：
C0（就绪 0 配对数）→ C1（就绪 0/1 配对数）→ C2（全部配对数）→
最小化最大 gap → 最小化 gap 总和。空方案的两个缺口指标均为 0。

实现建模为二分图最小费用流：源点到每个岗位、每个员工到汇点的容量均为 1，
天然保证"每岗最多一人、每人最多一次、不得改派"；候选人关系即岗位到员工的
容量 1 边。分三阶段求解：

1. **计数最优**：用分层大权重 `W0 >> W1 >> W2 >> 最大可能 gap 总和`
   （BigInt 精确计算）把 (C0, C1, C2) 的字典序编码进边费用，一次最小费用流
   即得计数最优解——权重间距超过所有低阶项总和，故不存在"用远期覆盖换
   当前覆盖"的空间。
2. **最小化最大 gap**：按候选边 gap 的去重排序值升序扫描阈值，在只允许
   `gap <= T` 的边时重解第一阶段，首个仍能达到最优计数的 `T` 即为最小化的
   最大 gap。
3. **最小化 gap 总和**：在 `gap <= T` 的边集上，把 gap 作为末位费用项
   （仍受分层权重压制）再解一次最小费用流。

最小费用流采用 SSP（逐条最短增广路，SPFA 求最短路，费用可为负，最短增广路
费用非负时停止），对整数容量给出精确整数最优解。测试包含与暴力枚举的
随机对照，验证任意小规模输入下指标逐项一致。

## 复杂度

设 `P` 为岗位数、`E` 为员工数、`K` 为候选关系数。单次最小费用流为
`O(F * V * U)`：`F <= min(P, E)` 次增广，每次 SPFA 为 `O(V * U)`，
其中 `V = P + E + 2`、`U = K + P + E`。阶段一、三各求解一次，阶段二至多
对 `K` 个去重阈值各做一次可行性求解，总体 `O(K * F * V * U)`，
对实际规划规模（数十至数百节点）毫无压力。
