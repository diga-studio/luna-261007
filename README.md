# VaultMint 分币估值账本

单资产代币的估值分摊账本：固定发行量 N，获批估值 V（美分，bigint），
按"基础金额 + 余数排名 +1 分"规则把 V 精确分摊到全部正余额持有人。

## 运行

```sh
npm install
npm test          # tsc 编译后用 node:test 运行全部测试
npm run build     # 仅编译到 dist/
```

## API

- `new VaultMintLedger(totalTokens, appraisalCents, holdings)` — 创建账本。
- `transfer(from, to, quantity)` — 转账，允许新持有人加入、原持有人清仓。
- `reappraise(appraisalCents)` — 采用新估值。
- `quote(holderId)` — 返回 `{ quantity, amount }`，无持仓者均为 0。

## 分摊规则

持币 q 的持有人：基础金额 `floor(V*q/N)`，余数 `(V*q) mod N`。
`K = V - Σ基础金额`，余数最大的 K 位持有人各 +1 分；同余数按 ID 的
ASCII 字典序优先。只有正余额持有人参与排名。

## 实现与复杂度

核心观察：V、N 不变时，每个持有人的 (基础金额, 余数) 只取决于自身持币量 q；
排名键为 `(余数降序, ID 字典序升序)`，前 K 名获得 +1 分。因此用两个堆维护
"前 K 名"集合与"其余人"集合的分界：

- `topHeap`：排名前 K 的持有人，按排名键的最小堆（堆顶是前 K 中最差的）。
- `restHeap`：其余持有人，按排名键的最大堆（堆顶是其余人中最好的）。
- 懒删除：持有人余额变化时版本号自增，旧堆条目成为惰性垃圾，弹堆时丢弃。
- 每次转账只移除/插入 2 个条目；`K = V - Σ基础金额` 中 Σ基础金额 随两次
  余额变化增量更新，单次转账 |ΔK| ≤ 1，故堆间迁移条目数为 O(1)。
- 垃圾条目超过存活条目 4 倍时重建两个堆（O(H)，摊还到每次操作 O(1)）。

复杂度（H 为当前正余额持有人数）：

- `transfer`：摊还 O(log H) —— O(1) 次堆操作 + 摊还 O(1) 重建。
- `quote`：O(1) —— 哈希表查询 + 一次 bigint 乘除。
- `create` / `reappraise`：O(H log H)（允许全量处理，排序建堆）。
- 空间：O(H) —— 只存当前正余额持有人；离场账户记录立即删除。

余数恒小于 N（≤ 1e6），用 number 存储；基础金额与 V 用 bigint，
支持超过 `Number.MAX_SAFE_INTEGER` 的估值；全程无浮点运算。

## 测试

- 规格示例：N=100、V=4，A→C 转账后未参与交易的 D 从 2 分变 1 分，转回后恢复。
- 随机对拍：独立全量重算参考模型（`src/reference.ts`）逐次核验随机转账与
  重估，覆盖大量相同余数、清仓后重新加入、超过安全整数的估值、守恒性。
- 规模测试：10 万持有人、2 万次转账穿插查询与重估，含新增/离场账户，
  打印耗时。
