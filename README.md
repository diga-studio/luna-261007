# clinic-slot-allocator

门诊连续号源分配库（TypeScript，纯进程内存，无接口层）。针对"只检查预约开始时刻"
的号源展示问题，本库保证：只有整个预约区间内的**每一分钟**剩余容量都大于 0，
时段才会被推荐或占用。

## 概念与约定

- 时间统一为 Unix 纪元以来的**整数分钟**；所有区间为 `[start, end)`，含开始、不含结束。
- 每位医生有一份初始化后不再修改的开放日历，由互不重叠（可首尾相接）的区段组成，
  每段容量为 1–8；未覆盖的时间容量为 0。
- 预约时长为 15 / 30 / 60 分钟，全程占用 1 个容量；允许跨越首尾相接的区段，
  不能跨越未开放的空档。
- 所有调用顺序执行；一次调用只涉及一位医生，医生之间容量互不影响。

## API

```ts
import { SlotAllocator } from "clinic-slot-allocator";

const allocator = new SlotAllocator();

// 注册医生及其开放日历（重复注册、区段重叠、容量越界会抛异常）
allocator.addDoctor("doctor-1", [
  { start: 0, end: 600, capacity: 2 },
  { start: 600, end: 1200, capacity: 1 },
]);

// 最早可预约时段查询：返回完整落在 [100, 2000) 内、能容纳 60 分钟的最早开始时间；
// 开始时间可以是任意整数分钟；无号返回 null；不占用号源。
const start: number | null = allocator.findEarliest("doctor-1", 100, 2000, 60);

// 指定时段占用：成功返回唯一预约标识，容量不足返回 null 且不留任何占用。
const id: string | null = allocator.book("doctor-1", 480, 30);

// 按标识取消：只释放该预约实际占用的容量；重复取消返回 false，不增加余量。
allocator.cancel(id);
```

## 实现要点

每位医生维护三棵以"分钟"为键的 treap 有序映射（`src/treap.ts`）：

- **runs**：剩余容量恒定的区间，预约/取消时在边界处分裂并就地增减容量；
- **good**：每一分钟剩余容量都 ≥ 1 的极大区间（占用降为 0 时切出，释放回到 1 时并入）；
- **long[d]**（d ∈ {15, 30, 60}）：长度 ≥ d 的 good 区间子集。

由此：

- `findEarliest` 只需在 `long[d]` 中做两次查找（包含 `queryStart` 的区间、
  其后的第一个区间），复杂度 `O(log n)`，不会被大量短于请求时长的空隙拖慢；
- `book` 的可行性检查是一次 `good` 查找 `O(log n)`，占用/释放为
  `O(k log n)`（k 为预约区间内已有的边界数，通常只有几十）；
- treap 优先级由键的确定性散列导出，无需随机源，行为可复现。

## 构建与测试

```sh
npm install
npm test        # 编译并运行全部测试（node:test，无其他运行时依赖）
npm run build   # 仅编译到 dist/
```

测试内容（`test/`）：

- `correctness.test.ts`：容量 >1、部分重叠、端点相接、跨容量变化边界、跨空档拒绝、
  取消语义等专项用例；小时间轴上与独立的逐分钟暴力实现（`test/brute.ts`）做
  穷举/随机对照，结果完全一致；随机交错的查询、占用、失败占用、重复取消核对，
  且取消全部有效预约后查询结果恢复为初始日历的结果。
- `stress.test.ts`：可重复运行的规模压测——100 位医生、2000 个日历区段、
  20 年跨度、20 万条有效预约（高度集中在一位医生身上并留下大量短空隙），
  5 万次查询与 1 万次成功占用/取消交错执行。断言总耗时 < 15 s、峰值 RSS < 384 MiB；
  并用独立的逐分钟占用模型核验每个返回时段确实可用、抽样核验不存在更早答案；
  另含"末尾才出现连续可用时段"的确定性用例。初始化耗时单独打印，不计入操作耗时。

参考运行（本机）：初始化约 0.4 s（另计），6 万次操作约 0.45 s，峰值 RSS 约 319 MiB。
