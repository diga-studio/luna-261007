# spherical-geofence

位置营销用的球面围栏匹配库（TypeScript）。围栏目录保存在进程内存中，由上层直接调用，无接口层。

## 使用

```bash
npm install
npm test        # 构建 + 运行全部正确性与规模测试
npm run build   # 仅构建到 dist/
```

```ts
import { FenceCatalog } from "spherical-geofence";

const catalog = new FenceCatalog();

// 整体载入（替换此前目录）
catalog.load([
  { id: "store-001", center: { lat: 31.2304, lon: 121.4737 }, radiusMeters: 500 },
  { id: "store-002", center: { lat: 89.95, lon: -30 }, radiusMeters: 5000 },
]);

// 按标识新增 / 修改（同 id 覆盖，立即生效）
catalog.upsert({ id: "store-001", center: { lat: 31.23, lon: 121.47 }, radiusMeters: 1000 });
catalog.upsertAll([/* ... */]);

// 按标识删除（id 之后可复用）
catalog.remove("store-002");

// 匹配单个位置，返回全部命中围栏的标识
const hits: string[] = catalog.match({ lat: 31.2305, lon: 121.474 });
```

## 规则与模型

- 地球按半径 6371008.8 m 的球体处理，距离为球面最短弧长（atan2 形式中心角，全距离数值稳定）。
- 纬度 [-90, 90]，经度 [-180, 180]；±180 为同一经线，极点上各经度为同一点。非法输入抛出 `RangeError`/`TypeError`。
- 半径 [50, 5000] m；命中判定为 距离 ≤ 半径 + 0.001 m（1 mm 向外容差，跨日界线与极点同样适用）。
- 匹配返回全部命中围栏标识，不重不漏；围栏可任意重叠、包含或完全相同。
- 所有修改对下一次 `match` 立即生效；调用按顺序执行，不提供并发保证。

## 索引设计

- 位置统一转换为地心直角坐标系下的单位向量，使用均匀三维网格索引（`src/grid-index.ts`）。
- 围栏（球冠 = 中心点 + 弦长半径的三维球）注册到所有与三维球相交的格子；查询只需检查位置所在单个格子。格子大小全球均匀，日界线与极点无特殊路径。
- 候选先经弦长平方预过滤（含 1 m 安全余量），再用精确球面距离 + 0.001 m 容差判定，保证与逐围栏独立计算的结果完全一致。

## 规模测试耗时记录

`npm test` 中的 `test/scale.test.ts`：20 万围栏、2 万次不同位置查询、期间穿插 2000 次单条新增/修改/删除，计时不含首次载入；计时结束后对抽样查询与逐围栏暴力计算逐一核对。本机（Apple Silicon, Node 24）实测：

| 场景 | 首次载入（不计时） | 计时段（2 万查询 + 2000 修改） | 预算 |
| --- | --- | --- | --- |
| 全球分散分布（30% 50m / 30% 5000m / 40% 混合） | ~2.4 s | ~38 ms | ≤ 30 s |
| 北纬 89.9° 以北集中分布（以 50m 为主、含 5000m） | ~0.1 s | ~177 ms | ≤ 30 s |

说明：按需求负载中每次查询命中不超过 20 个围栏。极区 20 万围栏集中在约 388 km² 内（约 515 个/km²），为满足该约束，极区场景的半径分布以小半径为主（同时包含 50 m 与 5000 m）；命中数超过 20 的查询位置在负载生成时被剔除。大量围栏共同覆盖同一位置时仍返回全部结果（见正确性测试 `massive overlap`），不计入上述耗时。
