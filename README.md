# retainage-allocator

AIA 进度付款申请（G702/G703）的扣留款整批分摊库。由上层财务程序调用，
批次输入与计算结果仅保存在进程内，不依赖任何外部服务。

## 规则

- 扣留比例固定 10%，首期期初累计扣留款为 0，不涉及扣留款释放。
- 每个分项每期的累计扣留款只能取其精确 10% 金额向下或向上取整到分的结果；
  精确金额已是整数分时必须保持该值。
- 同一期各分项累计扣留款之和，等于该期项目累计金额合计的 10% 四舍五入到分
  （恰好半分时向上进一分），保证 G702 汇总与 G703 分项精确对齐到分。
- 每个分项的累计扣留款不得随期次减少；本期新增 = 本期累计 - 上期累计。
- 在所有满足上述规则的完整方案中，选择所有分项、所有期次偏差之和最小的方案
  （偏差以十分之一分计：|累计扣留款分值 × 10 − 累计金额分值|）。
  偏差总和并列时，按期从早到晚、同期按输入分项顺序逐个比较累计扣留款，
  在第一处不同的位置取数值较小的方案。

## 使用

```ts
import { allocateRetainageBatch } from "retainage-allocator";

const result = allocateRetainageBatch({
  // periodsCents[期][分项]：累计已完工程与在场材料合计金额（整数分）。
  // 分项顺序固定；每个分项的累计金额不得随期次减少。
  periodsCents: [
    [4, 2],
    [4, 9],
  ],
});
// result.periods[t].items[i] = { cumulativeCents, currentCents }
```

## 方法

整批核算建模为时间轴上的最小费用循环流：

- 每期“向上取整”的个数 k_t 被合计约束唯一确定，作为时间轴前向边的固定流量；
- 每个分项在 floor 值不变的连续自由选择区段上构造一条反向链，
  流经区段边缘表示该期选择向上取整，自动保证累计扣留款单调不减；
- 边费用把“全局偏差最小”（主目标）与“并列时按指定位序取较小值”
  （次目标）编码进同一个 bigint 费用中求解，保证整批全局最优而非逐期贪心。
