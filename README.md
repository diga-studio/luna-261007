# 班组派工推荐库

由上层调度系统调用的 TypeScript 库：在进程内内存名册上，为一张工单推荐一支
**资格完整、总代价最低** 的班组（2 至 8 人，覆盖全部必需技能，至少一人可任领班）。

## 构建与测试

```bash
npm install
npm test        # 等价于 npm run build && node --test
```

仅依赖 Node.js 与 `typescript`（devDependency），无需数据库、Docker 或任何服务进程。

## 使用

```ts
import { CrewPlanner } from "crew-dispatch-recommender";

const planner = new CrewPlanner();

// 名册仅在推荐调用之间整体替换
planner.replaceRoster(workers);

// context 由上层按工人编号提供：该时段可用结论、单程里程、往返行程分钟数
const result = planner.recommendCrew(order, context);
// result === null 表示无合法班组；否则：
// { memberIds: number[] /* 升序 */, foremanId: number, totalCost: number }
```

## 业务规则要点

- 工人入选条件：时段可用、单程里程不超过个人出勤半径、未避配该客户、
  当天已排分钟数 + 本次工作分钟数 ≤ 600。
- 证书到期时刻 ≥ 工单结束时刻的技能才可覆盖要求；某项证书失效不影响其他有效技能。
- 个人代价 = 往返行程分钟数 + 当天已排工作分钟数 + (100 − 信用分)；班组总代价为成员之和。
- 最优判定：总代价最低 → 人数最少 → 成员编号升序序列字典序最小。
- 领班为成员中编号最小的可任领班者；领班同样贡献技能。

## 实现说明

- `src/planner.ts`：名册管理、资格过滤、候选构造、领班选定。
- `src/solver.ts`：精确动态规划。状态为 (已覆盖技能掩码, 人数, 是否已有领班)，
  保存每状态最低代价；代价相同保留字典序最小编号集合（人数相同的集合，
  字典序等价于成员位图最低不同位，且并入同一不相交集合后顺序不变，故按状态保留最优路径正确）。
  完全等价（技能掩码、代价、领班标记相同）的工人仅保留编号最小的 8 个。
- 规模 200 人 / 16 项必需技能时，单次推荐实测约 10ms（最坏构造约 300ms），
  峰值额外内存约 50MB，均远低于 5 秒 / 256MiB 的限制。

## 测试

- `test/planner.test.js`：小规模确定性场景，含“最便宜的工人不属于最优班组”、
  总代价平局、字典序平局、资格过滤边界（证书恰在结束时刻到期、当日 600 分钟恰满）、
  人数上下界、无解与名册替换。
- `test/fuzz.test.js`：固定种子随机场景与暴力枚举参照对拍（300 轮）。
- `test/perf.test.js`：200 人、16 项必需技能、候选大量共享技能的有解（已知最优答案）
  与无解场景，校验结果、耗时与峰值额外内存。
